# d2Cache — Dual Adaptive Caching for Diffusion-Based LLMs (2509.23094)

- arXiv: https://arxiv.org/abs/2509.23094
- HTML:  https://arxiv.org/html/2509.23094v1
- Code:  https://github.com/Kamichanw/d2Cache (ICLR'26)
- Models tested: LLaDA, Dream

## TL;DR

Training-free, approximate **KV cache** for dLLMs. Adaptively decides at each
decoding step which tokens get their KV refreshed and which reuse cached KV.

## Mechanism

Two-stage **per-token** selection (NOT per-head):

1. **Certainty prior** (Eq. 3–4): for each masked position, compute a
   Gaussian-weighted density of decoded/prompt tokens within a window
   (σ=10). Tokens whose local context just changed get higher refresh
   priority. The "scope" here is a fixed, isotropic Gaussian window in
   sequence-position space — uniform across heads and layers.
2. **Attention rollout** on remaining tokens to pick which ones still
   need a KV update.

Selected tokens have Q/K/V recomputed; others reuse cached KV. The cache
is the standard **KV tensor cache**, not an attention-output cache.

## Relation to our scope-driven idea

| dimension              | d2Cache                                  | ours (planned)                                       |
|------------------------|------------------------------------------|------------------------------------------------------|
| cache granularity      | per-token KV                             | per-(layer, head, query) **attention output**         |
| invalidation trigger   | Gaussian density of decoded tokens       | scope(head, query) ∩ U_k ≠ ∅                          |
| scope                  | single isotropic σ (sequence position)   | per-head: sink_set ∪ ±window from probe              |
| heterogeneity          | uniform across heads                     | mask_binder ±5, punct_sink global, bidir_asym ±150   |
| compute path           | recompute Q/K/V then attend              | reuse attention OUTPUT entirely if scope safe         |

**Overlap:** Both reuse based on "did the input that this position depends
on change?". d2Cache approximates that with a single Gaussian window
shared across heads.
**Gap we cover:** Heterogeneous per-head scope from observation
(`universal_sink_window_abstraction`), and caching at the
attention-output level rather than KV level — so a "safe" head skips both
the QK matmul and the softmax×V matmul, not just the K/V projection.

## Why this paper does NOT subsume us

- Single isotropic σ ≠ per-head sink+window scope. Heads with global
  punctuation sinks (`punct_sink`) get no benefit from a position-local
  Gaussian.
- KV cache reuse still requires running the attention matmul over the
  full (Q × K) grid for the affected query; our design skips the matmul
  entirely on safe heads.
- No event-driven semantics ("scope ∩ U_k = ∅"): the criterion is
  continuous-density, not set-disjoint.
