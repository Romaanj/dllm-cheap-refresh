# ELF: Embedded Language Flows

- **arxiv**: 2605.10938 (May 2026)
- **URL**: https://arxiv.org/abs/2605.10938
- **code**: https://github.com/lillian039/ELF
- **authors**: Hu, Qiu, Lu, Zhao, Li (Tianhong), Kim, Andreas, He (Kaiming) — MIT

## Summary

Continuous-time **Flow Matching** language model. Trajectory lives entirely in
T5 embedding space; discretization happens **only at t=1** via a
**shared-weight** "decode mode" of the same denoiser (unembedding matrix W).
No separate decoder, no per-step rounding/CE, no simplex constraint.

## Family placement (vs discrete masked DLM work in this repo)

ELF is a **different family** from LLaDA / Dream / Fast-dLLM / MDLM / Duo.
- No remasking schedule, no confidence sampler → inverse-CDF / FastGen-style
  scope work has **no surface** to attach to.
- KV cache reuse is **not applicable**: every position's z_t changes every
  step. Step count comparisons hide that per-step cost is dense.
- Sequence length fixed at z₀ shape — no EOS-driven variable length in paper.

## Key design choices (with mech reasons)

- **x-prediction** (predict clean embedding) not v-prediction.
  Reason: aligns with final-step W·x_θ → logits. v-pred breaks weight sharing
  empirically.
- **80% ℒ_MSE / 20% ℒ_CE**, single batch, two masked branches → no extra
  forward cost.
- **mode token** (denoise / decode) + time t conditioning on a single
  network.
- **Self-conditioning** (Analog Bits, 50% prob) gives the conditioning
  signal `c` for CFG without paired data.
- **Training-time CFG** (Mean Flow lineage) → models v_cfg in single pass,
  no 2× inference cost.

## Embedding ablation (Fig 5a) — non-obvious

Ordering (best → worst): pretrained contextual T5 ≫ scratch encoder
(OWT-trained from T5 obj) > pretrained token (non-contextual) > Gaussian >
**learnable**. Jointly learning denoiser + embedding is the **worst** — likely
collapse. Strong evidence that the embedding geometry must be fixed by an
external objective.

Bottleneck 512→128→hidden works fine → weak signal on intrinsic dim of
text embedding manifold.

## Sampler

SDE-inspired sampler **substantially** beats ODE in few-step regime
(Fig 5c: 8–32 step). ODE only catches up past ~128 steps. Mechanism left
implicit; framed as "stochasticity reduces error accumulation."

- **FLM / Flow Map LM** [30] arxiv 2602.16813 (2026)
- **CoDAR** [62] arxiv 2603.02547 (2026)
- **DFM / CFM / FMLM** various — token-level CE along trajectory, distillation for few-step

All carry per-step token-level CE supervision; ELF's distinction is exactly
the absence of that.

## What I would test next

1. **Cross-family compute fairness**: 32 SDE steps × full denoiser pass on
   1024 tokens vs LLaDA-8B 16 step with KV cache — wall-clock, not step count.
2. **Variable length**: ELF has no EOS mechanism in the paper. Practical
   sequence generation?
3. **Why SDE crushes ODE so cleanly at 8–32 step**: probably the most
   transferable finding to other flow-LM work.
4. **What does the embedding bottleneck (128-d) buy?** Connection to
   semantic intrinsic-dim literature.
